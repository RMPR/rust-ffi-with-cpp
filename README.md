# Rust FFI with C++

A [presenterm](https://github.com/mfontanini/presenterm) talk. Every code
sample on the slides is either pulled from a file in `demos/` that compiles,
or is a snippet that runs live.

## Running it

Run everything **from this directory**: snippets use paths relative to it.

```sh
make present   # pre-builds the demos, then starts the talk
make dev       # edit mode: validates snippets and slide overflow on each reload
```

During the talk, `Ctrl+E` runs the snippet on the current slide.

Needs: `presenterm` (0.16+), a Rust toolchain (2024 edition), a C/C++
compiler, `ar`, `nm`, and libclang (for bindgen).

The two diagram slides show `abi-diagram.png` and `hourglass.png`, so present in a terminal that can
display images (ghostty, kitty, wezterm, konsole). In one that cannot, such
as Ptyxis, it degrades to coarse blocks. The images are generated from the
matching `.mmd` files; to regenerate them after an edit:

```sh
mmdc -i abi-diagram.mmd -o abi-diagram.png -s 3 -t dark -b transparent
mmdc -i hourglass.mmd -o hourglass.png -s 3 -t dark -b transparent
```

That needs mermaid-cli and the Chromium path in `.puppeteerrc.json`, but
only when regenerating, not when presenting.

## How the code samples are kept honest

* **Excerpts** use presenterm's `file` snippets with `start_line`/`end_line`,
  so slides show the real demo sources. If you edit a demo file, re-check the
  line ranges of the slides that quote it.
* **Runnable snippets** are tagged `+exec +validate`. With
  `--validate-snippets` (what `make dev` passes), presenterm runs all of them
  on load and reports the slide of any that fails. The one snippet that is
  meant to abort is tagged `+expect:failure`.
* **Every command is on the slide.** Shell snippets have no hidden lines:
  what the audience reads is exactly what runs, from this directory.
* `config.yaml` enables execution, switches Rust snippets to the 2024
  edition, and runs shell snippets with `bash -eo pipefail` so a failing
  step cannot go unnoticed.
* Demos 01 to 05 use no crates, so the slides build them with bare `cc`,
  `c++`, `ar` and `rustc` into each demo's `build/` directory. Cargo only
  appears afterwards, first to show what it automates (demo 02 again, via
  `build.rs`), then because bindgen, cbindgen and cxx are crates.
* Slides were sized to fit a 100x32 terminal, live output included. Code
  lines are kept to 76 columns (`demos/rustfmt.toml`).

## Demos

| Directory            | What it shows                                        |
|----------------------|------------------------------------------------------|
| `01-abi`             | Mangled vs. unmangled symbols (`nm`)                 |
| `02-rust-calls-c`    | Rust calling C: bare `rustc`, then `build.rs`        |
| `03-cpp-calls-rust`  | C++ calling a Rust `staticlib`, hand-written header  |
| `04-cpp-class-shim`  | A C++ class behind an `extern "C"` shim, used by Rust |
| `05-sharp-edges`     | String ownership across the boundary, `catch_unwind` |
| `06-bindgen`         | Demo 02 again, declarations generated by bindgen     |
| `07-cbindgen`        | Demo 03 again, header generated by cbindgen          |
| `08-cxx`            | The demo 04 class again, bridged by cxx with no shim  |
